# Описание HTTP API

Базовый адрес при локальном запуске: `http://127.0.0.1:8000`.
Интерактивная документация (Swagger UI) генерируется автоматически: `/docs`, схема OpenAPI: `/openapi.json`.

## Общие правила

- Данные передаются в формате JSON (`Content-Type: application/json`).
- Все адреса `/api/...`, кроме входа, требуют авторизации. После `POST /api/auth/login` сервер ставит cookie `session`, её нужно передавать в следующих запросах.
- Количества и деньги передаются строками (`"10.500"`, `"520.00"`), чтобы не терять точность. В запросах можно передавать и числа.
- Каждый ответ содержит заголовок `X-Request-ID` — по нему запрос находится в журнале.

### Коды ответов

| Код | Когда |
|---|---|
| 200 / 201 / 204 | успешно / создано / удалено (без тела) |
| 401 | не выполнен вход или неверный пароль |
| 403 | недостаточно прав (удаление доступно только администратору) |
| 404 | запись не найдена |
| 409 | нарушено правило предметной области (дубликат, проведённое поступление, удаление используемой записи) |
| 422 | некорректные данные запроса |
| 500 | внутренняя ошибка сервера |
| 503 | `/health`: база данных недоступна |

### Формат ошибок

```json
{ "detail": "Поступление уже проведено, изменять или удалять его нельзя" }
```

Ошибка проверки данных (422) дополнительно содержит список полей:

```json
{
  "detail": "Некорректные данные запроса",
  "errors": [
    { "field": "name", "message": "Поле не может быть пустым" },
    { "field": "short_name", "message": "Максимальная длина: 10" }
  ]
}
```

Ответ 500 содержит `request_id` для поиска в журнале.

## Служебное

| Метод | Адрес | Описание |
|---|---|---|
| GET | `/health` | проверка работоспособности приложения и БД, без авторизации |

```json
{ "status": "ok", "db": "ok", "version": "0.1.0" }
```

При недоступной БД: код 503, `{"status": "error", "db": "unavailable", ...}`.

## Авторизация

| Метод | Адрес | Тело | Ответ |
|---|---|---|---|
| POST | `/api/auth/login` | `{"username": "admin", "password": "..."}` | 200, данные пользователя; 401 при неверном пароле |
| POST | `/api/auth/logout` | — | 204 |
| GET | `/api/auth/me` | — | `{"id": 1, "username": "admin", "role": "admin"}` |

Роли: `admin` (администратор) и `storekeeper` (кладовщик). Пользователи создаются командой `python -m app.cli create-user`.

## Единицы измерения

| Метод | Адрес | Описание | Права |
|---|---|---|---|
| GET | `/api/units` | список | все |
| POST | `/api/units` | создать | все |
| GET | `/api/units/{id}` | получить | все |
| PUT | `/api/units/{id}` | изменить | все |
| DELETE | `/api/units/{id}` | удалить (409, если используется в материалах) | admin |

Тело запроса:

```json
{ "name": "Килограмм", "short_name": "кг" }
```

## Материалы

| Метод | Адрес | Описание | Права |
|---|---|---|---|
| GET | `/api/materials` | список с остатками | все |
| POST | `/api/materials` | создать (остаток = 0) | все |
| GET | `/api/materials/{id}` | получить | все |
| PUT | `/api/materials/{id}` | изменить название, единицу, описание | все |
| DELETE | `/api/materials/{id}` | удалить (409, если остаток > 0 или есть поступления) | admin |

Тело запроса (поле `stock` не принимается — остаток меняется только поступлениями):

```json
{ "name": "Цемент М500", "unit_id": 1, "description": "мешки по 50 кг" }
```

Ответ:

```json
{
  "id": 1,
  "name": "Цемент М500",
  "unit": { "id": 1, "name": "Килограмм", "short_name": "кг" },
  "stock": "40.000",
  "description": "мешки по 50 кг"
}
```

```json
}
```

## Поступления

| Метод | Адрес | Описание | Права |
|---|---|---|---|
| GET | `/api/receipts?status=draft\|posted` | список, фильтр по статусу необязателен | все |
| POST | `/api/receipts` | создать черновик (строки можно передать сразу) | все |
| GET | `/api/receipts/{id}` | получить со строками | все |
| DELETE | `/api/receipts/{id}` | удалить черновик (409 для проведённого) | admin |
| POST | `/api/receipts/{id}/items` | добавить строку в черновик | все |
| DELETE | `/api/receipts/{id}/items/{item_id}` | убрать строку из черновика | все |
| POST | `/api/receipts/{id}/post` | **провести**: увеличить остатки, закрыть для изменений | все |

Создание (`receipt_date` по умолчанию — сегодня):

```json
{
  "supplier_id": 1,
  "receipt_date": "2026-10-16",
  "comment": "первая партия",
  "items": [
    { "material_id": 1, "quantity": "40", "price": "520" },
    { "material_id": 2, "quantity": "1500", "price": "1.80" }
  ]
}
```

Строка: `quantity` > 0 (до 3 знаков после запятой), `price` ≥ 0 (до 2 знаков).

Ответ:

```json
{
  "id": 1,
  "supplier": { "id": 1, "name": "ООО «СтройБаза»" },
  "receipt_date": "2026-10-16",
  "status": "posted",
  "comment": null,
  "created_by": { "id": 1, "username": "admin" },
  "created_at": "2026-10-16T14:51:57.638372+03:00",
  "posted_at": "2026-10-16T14:51:57.706906+03:00",
  "items": [
    {
      "id": 1,
      "material": { "id": 1, "name": "Цемент М500" },
      "quantity": "40.000",
      "price": "520.00",
      "amount": "20800.00"
    }
  ],
  "total": "20800.00"
}
```

Ошибки проведения: 409 — поступление уже проведено или в нём нет строк.

## Пример сессии через curl

```bash
curl -c cookies.txt -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"..."}' http://127.0.0.1:8000/api/auth/login

curl -b cookies.txt http://127.0.0.1:8000/api/materials

curl -b cookies.txt -X POST http://127.0.0.1:8000/api/receipts/1/post
```
